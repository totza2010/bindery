### Added
- **Add Book now describes each result instead of listing bare titles.** A search fans out across every configured provider and returns them merged, so one title arrives several times over: searching *Harry Potter and the Order of the Phoenix* returned seven rows, among them the novel, the sheet music credited to John Williams, the film score credited to Nicholas Hooper, a Ladybird children's edition, and two entries carrying no author at all. They were indistinguishable without adding one and looking at what turned up. Each result now carries four things it did not before:
  - **The catalogue it came from**, so the Hardcover record and the OpenLibrary one can be told apart before choosing. Results whose provider was never recorded fall back to the prefix on their foreign ID, and show no label when even that says nothing.
  - **A link to that record on the provider's own site**, where the public URL can be built from the id already stored — OpenLibrary and Google Books today. Everywhere else the label stays plain text rather than offering a link that 404s. Linked labels carry the same `↗` and hover underline the rest of the app's outbound links use, and open in a new tab so a search in progress is not lost.
  - **The series it belongs to and its place in it**, read from Hardcover, which reports both and which nothing downstream had ever shown. A result in a series now reads `#5 Harry Potter`, ticked and highlighted when the library already holds that series, so a book continuing something you collect is distinguishable at a glance from one that starts something new. The library is checked on the server against both the series' own provider ID and any Hardcover link added by hand, so a series you created yourself and linked afterwards counts as held. Providers that report no series, and standalone books, carry no label.
  - **Whether you already own it.** Results the library holds read **In library** and cannot be added a second time. The check is by provider ID, so it recognises the same book however its title is written, and it is scoped to your own library — one user is never told what another has added.

  If the library cannot be read the results still arrive, simply without the marks.

### Fixed
- **A Hardcover search result's series is read correctly instead of as an internal identifier and a printed object** — Hardcover's search index returns `featured_series` as the book's *row* in the series: that row's own id, the position, and the series itself nested one level down. Bindery read the outer id, so every series a search reported was addressed by a number that resolves to nothing — for *Order of the Phoenix*, 304420 instead of the 1185 that identifies Harry Potter. It then looked for the name where there was none and fell back to the nested object, which reached the interface rendered as `map[books_count:34 id:1185 name:Harry Potter primary_books_count:7 slug:harry-potter]`. Neither fault was visible until the series was put on screen. Both values now come from the series itself; the older flat shape, where the name sits at the top level, still works.
