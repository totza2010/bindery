### Fixed
- **A search result's series is read correctly instead of as an internal identifier and a printed object** — Hardcover's search index returns `featured_series` as the book's *row* in the series: that row's own id, the position, and the series itself nested one level down. Bindery read the outer id, so every series a search reported was addressed by a number that resolves to nothing — for *Order of the Phoenix*, 304420 instead of the 1185 that identifies Harry Potter. It then looked for the name where there was none and fell back to the nested object, which reached the interface rendered as `map[books_count:34 id:1185 name:Harry Potter primary_books_count:7 slug:harry-potter]`. Both now come from the series itself. The older flat shape, where the name sits at the top level, still works.
